## Practice Quiz

### 1. Basic Concepts

1. **Question:** What are the primary differences between a PL/SQL function and a PL/SQL procedure?  
   **Sample Answer:**  
   - **Function:** Must return a value using a RETURN clause; can be invoked from SQL statements (e.g., within SELECT queries); typically used for calculations or returning a computed value.  
   - **Procedure:** Does not return a value by itself (though it can use OUT or IN OUT parameters to return data); is designed to perform actions (e.g., update records); typically called as a PL/SQL block and cannot be used directly in SQL.

2. **Question:** Explain the purpose of exception handling in PL/SQL. Why is it important?  
   **Sample Answer:**  
   - Exception handling enables your PL/SQL program to deal with runtime errors gracefully. Instead of terminating abruptly, code in the EXCEPTION block will catch errors (e.g., NO_DATA_FOUND, ZERO_DIVIDE) and allow you to log them, rollback transactions, or display meaningful error messages. This is crucial for data integrity and ensuring that your application remains robust.

### 2. Control Structures

3. **Question:** Write a PL/SQL block using an IF-THEN-ELSIF-ELSE statement that assigns a grade based on a numerical score.  
   **Your Answer Example:**
   ```sql
   DECLARE
     score NUMBER := 85;
     grade CHAR(1);
   BEGIN
     IF score >= 90 THEN
       grade := 'A';
     ELSIF score >= 80 THEN
       grade := 'B';
     ELSIF score >= 70 THEN
       grade := 'C';
     ELSIF score >= 60 THEN
       grade := 'D';
     ELSE
       grade := 'F';
     END IF;
     DBMS_OUTPUT.PUT_LINE('Grade is ' || grade);
   END;
   /
   ```

4. **Question:** What is the difference between a simple loop, a WHILE loop, and a FOR loop in PL/SQL?  
   **Sample Answer:**  
   - A **simple loop** executes endlessly until an explicit EXIT condition is encountered.  
   - A **WHILE loop** tests a condition before each iteration and executes as long as the condition remains true.  
   - A **FOR loop** runs a predetermined number of times by automatically iterating over a specified range. The loop variable is implicitly managed.

### 3. Cursors

5. **Question:** Compare implicit and explicit cursors. Provide one example of when you would use each type.  
   **Sample Answer:**  
   - **Implicit Cursors:** Created automatically by Oracle when you execute a single-row query (e.g., SELECT INTO). They are simpler because you don’t manage them explicitly.  
     - *Use Case:* When updating a single record or when using SELECT INTO in a block.  
   - **Explicit Cursors:** Declared by the developer for handling multiple rows. They allow you to control row-by-row processing with OPEN, FETCH, and CLOSE commands.
     - *Use Case:* When processing large result sets—for example, looping through all employee records and performing custom computations on each row.

6. **Question:** List and explain at least three cursor attributes (e.g., %FOUND, %ROWCOUNT, %ISOPEN) and their usage.  
   **Sample Answer:**  
   - **%FOUND:** Returns TRUE if the last FETCH statement found a row; useful to check after a fetch.  
   - **%NOTFOUND:** Returns TRUE if the last FETCH did not return a row, indicating that the end of the result set has been reached.  
   - **%ROWCOUNT:** Provides the number of rows that have been processed (or affected) by the cursor.  
   - **%ISOPEN:** For explicit cursors, returns TRUE if the cursor is open; it is always FALSE for implicit cursors.

### 4. Advanced Bulk Processing

7. **Question:** What is BULK COLLECT and how does it improve performance in PL/SQL?  
   **Sample Answer:**  
   - BULK COLLECT allows you to fetch multiple rows from a query into a collection (e.g., nested table, associative array) with a single context switch between SQL and PL/SQL. This minimizes the overhead incurred with row-by-row processing and significantly speeds up operations on large data sets.

8. **Question:** Explain how the FORALL statement works and why it is used.  
   **Sample Answer:**  
   - FORALL is used for performing bulk DML operations. It reduces context switches by executing a DML statement (INSERT, UPDATE, DELETE) on an entire collection. When combined with BULK COLLECT and SAVE EXCEPTIONS, it offers efficient batch processing and error handling.

### 5. Ref Cursors and Dynamic SQL

9. **Question:** Describe what a REF Cursor is and give an example scenario where it is useful.  
   **Sample Answer:**  
   - A REF Cursor is a cursor variable that can be passed as a parameter and can point to different query result sets dynamically at runtime. It is useful for functions that return a result set to a client application, especially when the structure of the query might change. For example, returning search results based on user-defined filter criteria.

10. **Question:** In your own words, explain the benefits of using dynamic SQL with the DBMS_SQL package.  
    **Sample Answer:**  
    - Dynamic SQL allows you to construct and execute SQL statements at runtime. Using the DBMS_SQL package gives you the flexibility to handle SQL statements whose structure is not known until runtime. This is especially useful for applications where the query may change based on user input or business logic. It also provides fine-grained control over SQL execution and robust error handling.

## Real-World Project Ideas

### 1. Payroll Processing System

**Objective:**  
Create a system for calculating employee salaries, bonuses, taxes, and generating payroll reports.

**Concepts Covered:**  
- **Functions/Procedures:**  
  Use functions to calculate monthly and annual salaries, bonus amounts, and tax deductions.
- **Explicit Cursors:**  
  Loop through employees in a department and compute payroll details individually.
- **Exception Handling:**  
  Handle errors such as missing salary data or invalid bonus calculations.
- **Bulk Operations:**  
  Use BULK COLLECT to fetch employee records and FORALL to apply bulk updates when issuing payroll adjustments.

**Project Tasks:**  
- Design a set of procedures:
  1. `calculate_bonus(p_employee_id NUMBER)` – Computes bonus based on performance.
  2. `update_payroll` – Loops through employees, calculates total pay (base salary + bonus – tax), and updates a payroll table.
- Develop a ref cursor function that returns payroll details for a department, then display results in an application report.
- Implement detailed exception handling to log errors (e.g., absent records).

### 2. Order Management and Inventory System

**Objective:**  
Build a system to handle customer orders, update inventory, and manage order processing.

**Concepts Covered:**  
- **Control Structures:**  
  Use conditional statements to validate order details (e.g., check if order quantity exceeds available stock).
- **Cursors:**  
  Use explicit cursors to process orders row-by-row for actions like updating inventory and inserting records into an order history table.
- **Dynamic SQL:**  
  Utilize DBMS_SQL for flexible query execution if order parameters are dynamic.
- **Error Handling:**  
  Implement exception blocks to catch issues such as insufficient inventory (using `RAISE_APPLICATION_ERROR`), duplicate order numbers, and runtime errors.

**Project Tasks:**  
- Create a procedure `process_order(p_order_id NUMBER)` that:
  1. Validates the order details.
  2. Uses a cursor to fetch items from an `order_items` table.
  3. Updates inventory for each item using bulk operations.
  4. Inserts order confirmation records.
- Use ref cursors in functions returning pending orders.

### 3. Employee Performance Review System

**Objective:**  
Develop a system for tracking employee performance reviews, calculating performance scores, and generating annual review reports.

**Concepts Covered:**  
- **Functions and Procedures:**  
  Write functions to compute performance scores (e.g., based on targets achieved, attendance records, etc.) and procedures to store results.
- **Control Structures:**  
  Apply IF-THEN-ELSIF logic to determine performance grades.
- **Explicit Cursors:**  
  Use explicit cursors to iterate through employee records from multiple departments, combining data from performance review and attendance tables.
- **Bulk Operations:**  
  Use BULK COLLECT to gather performance data and FORALL to update multiple review records efficiently.
- **Error Handling:**  
  Include exception blocks to manage issues like missing data or invalid score computations.

**Project Tasks:**  
- Create a function `calculate_performance_score(p_employee_id NUMBER)` that returns a score based on various metrics.
- Develop a procedure `update_performance_reviews` that processes all employees’ data, determines review grades, and updates a performance table.
- Implement a report-generating function using a ref cursor that lists employees by department along with their review scores and comments.
